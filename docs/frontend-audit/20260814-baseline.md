# 前端重构基线审计

## 当前结构

- Vue Router 当前共 38 个实际路由记录（含公开页、布局重定向和子页面；不计守卫中的跳转对象）。
- 全局 `styles.css` 共 1,103 行，同时存在多个页面 scoped CSS。
- 最大单页是领导大屏；客户新建/编辑、团队数据、客户列表和客户详情也存在较多页面级布局逻辑。
- 普通业务页以明亮卡片为主，领导大屏是独立深色视觉体系；这一区分在重构后保留。

## 已确认的冲突

| ID | 冲突 | 已确认处理 |
|---|---|---|
| UI-C01 | 大屏总量按全部年级，客户排行榜硬编码为 2026/26 级 | 增加管理员可配置“重点年级”，排行榜和两校对比统一使用 |
| UI-C02 | A 类超时提醒可配置，新大屏需求为 3 日 | 复用同一组织策略，默认 3 日，大屏显示实际生效阈值 |
| UI-C03 | 已有人工调用的 AI 摘要/建议，新需求要求自动分析 | 保留原入口；自动分析作为独立、版本化、只读的客户智能卡 |
| UI-C04 | 全局 CSS 中大量页面样式与响应式覆盖集中在同一文件 | 拆分为 tokens/base/layout/components/pages，页面不再覆盖基础组件语义 |

## 后续发现原则

新发现的功能语义冲突不默认删除或合并。在用户确认前，保留两种能力并使用明确名称；视觉层可统一，业务语义不自行改写。

## 本轮第一阶段重构结果

- 建立独立 `styles/design-system.css`，统一背景、表面、文字、品牌色、圆角、阴影、动效曲线和降级动效。
- 统一侧栏、导航、面板、表单、按钮、表格、抽屉和弹窗的视觉语义；保留各业务流程和权限判断。
- 普通业务页面使用明亮、克制的 Apple 风格 SaaS 视觉；领导大屏继续使用深色电影化视觉，不让两套场景互相覆盖。
- 新增客户智能分析卡与管理员配置页面，结果明确标记为只读，不自动覆盖正式档案。
- 当前阶段不拆分 38 个路由的业务组件；后续按下表逐模块迁移，避免一次重写引入业务回归。
