# ADR 0001: 采用模块化单体

- 状态：已接受
- 日期：2026-07-19

## 决策

第一版将后端作为一个 Spring Boot 进程部署，按 `api/application/domain/infrastructure` 划分功能模块。跨模块只调用 application port，不直接访问其他模块的 Repository。

## 理由

当前数据量和团队规模不需要微服务的运维成本。清晰的模块边界可以保留未来拆分的可能，同时保证客户、沟通、提醒和审计可参与同一数据库事务。

## 后果

所有业务表携带 `organization_id`，所有入口复用同一权限范围解析逻辑。如果未来拆分，需要先为模块间调用增加显式事件或接口。
