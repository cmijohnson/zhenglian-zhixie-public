# QQ 对话、A 类协作、咨询交接与客户资料补全

本文说明本次新增能力的业务行为、权限边界、部署要求和运维注意事项。所有接口均从当前登录会话推导组织和成员，不接受客户端传入 `organizationId`。

## 1. 功能总览

### 1.1 QQ 对话

员工在“QQ 对话工作台”创建自己的工作 QQ 连接并扫码。每名成员同时最多保留一个有效连接。连接成功后，页面以同源 iframe 嵌入固定版本的完整 QQ Chat Exporter WebUI，可分页加载全部好友和群聊，并合并临时会话、服务号和设备会话。搜索覆盖备注、昵称、QQ/群号，300 ms 防抖后按“号码精确 → 前缀 → 包含”排序。员工先选会话并即时预览最近 50 条，滚动或翻页查看历史，也可以使用日期、消息搜索、媒体、导出、任务、表情、群文件和群相册等工作台能力；此阶段不选择 CRM 客户、不调用 AI、也不创建导入记录。

只有点击工作台中的“同步到客户云”才打开 CRM 抽屉。私聊和临时会话按 QQ 号唯一匹配；无匹配可快速建档，多匹配或 QQ 冲突必须人工处理。群聊还必须选择目标成员，并勾选“包含第三方对话，已确认具有业务必要性”。AI 只能把目标成员的消息当作客户证据，其他成员发言仅作上下文。员工核对并确认草稿后，系统才向同一客户档案写入一条 `QQ导入` 时间线记录。

系统以“组织、连接、会话类型、会话 ID、时间范围、消息哈希、客户”防止同一段消息重复导入，并以“组织、成员、幂等键”防止浏览器重试造成重复时间线。AI 不可用时返回空白人工草稿，不阻止员工整理和保存。

原始消息使用 AES-256-GCM 加密后写入独立数据卷，默认保留 30 天。数据库仅保存索引、哈希、相对文件路径和清理时间。消息图片及媒体地址在服务端改写成 5 分钟有效、绑定当前成员和 QQ 实例的加密票据；代理只允许受信任 QQ 域名或当前实例内的受控下载路径，最多 2 次安全重定向、50 MB、仅图片/音频/视频/二进制媒体且 `Cache-Control: no-store`。浏览器不会得到 QCE Token、Bridge Token、Docker 接口或宿主文件路径。原文仅导入人、当前负责人、有效协作成员和组织管理员可查看；MCP、日志、审计和普通导出不返回原文。

### 1.2 A 类客户协作

系统以“客户质量”分类中的 `A类用户` 标签作为规则入口。有效跟进人数等于启用的主负责人加有效编辑协作成员：

- 少于 2 人时自动创建或更新一条公开招募；
- 满足 2 人时自动关闭招募；
- 协作人停用、退出或移除后重新招募；
- 客户归档或取消 A 类后取消未完成招募；
- 主负责人无效时保持招募并向管理员产生负责人异常提醒。

首页展示“重点客户协作招募”。可写角色领取前能查看完整 CRM 档案和最近时间线，但看不到 QQ 原文、绩效证据或密钥。领取使用行锁、人数复核和唯一约束；满员后的并发请求返回稳定冲突码，不会创建重复授权。

组织策略默认启用 72 小时无有效更新提醒，每天北京时间 09:00 评估。管理员可以关闭或设置 1–30 天阈值和通知时间。人工沟通、确认后的 QQ 跟进和咨询结果会完成旧提醒；浏览、标签和负责人修改不会刷新跟进时钟。每个跟进人只保留一条未完成自动提醒，调度重跑不会堆积重复记录。

### 1.3 咨询交接

咨询交接使用独立表单和不可变客户快照，普通沟通表单保持轻量。提交前至少引用一条当前客户时间线，并填写咨询原因、客户原话、目标与动机、已做行动、主要顾虑、产品适配、建议重点、禁忌和预期结果。决策参与人是可选字段；填写时必须确认“客户自愿提供且业务必要”。

默认营业时段 09:00–21:00，至少提前 30 分钟，可选 30、45、60、90 分钟，每名顾问每天最多 6 场。管理员可配置以上参数。系统用顾问和日期级数据库事务锁串行化预约校验，待接受、已排期和待回填时段均参与冲突判断。

固定流程为：

`待顾问接受 → 已排期 → 待结果回填 → 已完成`，也可进入 `已拒绝` 或 `已取消`。

顾问接受后自动获得同一客户的编辑型协作权限。结果回填保存结果、是否推进、下一步、下一负责人和下次时间；未推进必须选择管理员维护的失败原因，“其他”必须补充说明。系统生成一条不可重复的结构化时间线，并把新提醒分配给表单指定的下一负责人。结果截止默认是实际结束后 48 小时，逾期分阶段提醒顾问、主负责人和管理员。

### 1.4 客户资料补全

客户新增两个独立字段：

- `highSchool`：高中学校；
- `sourceLocation`：学生生源地。

它们不复用大学 `school` 或当前城市 `city`。管理员通过“客户资料补全”上传 XLSX，先预览行级匹配结果，再确认提交，并可下载 CSV 报告或回看历史任务。

模板必须含 `Sheet1` 和 `所在地映射`。匹配严格使用规范化后的“姓名 + 专业 + 年级”，不做模糊姓名匹配。明确年级列优先；没有年级列时从班级受控解析。只使用映射表中的实际值，不依赖工作簿查找公式。

提交只补空字段，绝不覆盖 CRM 已有值。高中冲突、映射待核实、无客户、多客户和年级不符均逐行跳过。预览 24 小时失效；同一组织相同文件 SHA-256 幂等。

API–MCP 清单已经登记结构化招募查询/领取、咨询查询/草稿/提交。QQ 扫码、完整工作台、原始消息、媒体和 XLSX 文件继续标记为认证控制面或文件能力，不向 MCP 暴露。`qce/**` 不是任意 HTTP 代理：Java 和 Bridge 双层核对同一份固定方法/路径能力集，未登记路径、路径穿越、宿主控制、任意 URL 和跨实例切换全部拒绝。

## 4. QQ Bridge 架构与部署

`qq-bridge/` 是受限 TypeScript 服务，通过内部 Docker 网络管理固定镜像的 QCE 实例。它不向宿主机发布端口；所有工作台 HTTP 与 WebSocket 请求必须携带后端专用 Bridge 凭据、命中固定能力白名单，并由 Bridge 根据当前成员的实例在服务端注入 QCE Token。配置读写会删除 Token、监听地址、端口、宿主路径和 Docker 字段，平台控制面的打开目录、修改监听和任意请求能力不开放。每个实例使用独立容器与四个命名卷（QQ 会话、导出数据、二维码缓存、NapCat 配置），默认导出配额 10 GB；磁盘剩余低于 15% 时停止新导出。显式配置卷覆盖上游镜像的匿名配置卷，确保含凭据的配置可按成员归属并在撤销时确定性清理。QCE 容器丢弃全部 Linux capabilities 后只加回启动所需能力，不包含 `SYS_ADMIN` 或 `NET_RAW`，并使用 `none` 日志驱动避免上游生成的凭据进入 Docker 持久日志。

上游 `qq-chat-exporter` 固定在提交 `58fc533f1bfdbf4535be0f83af4e595d4d7ecf27`。构建脚本校验提交和 GPL-3.0 许可证，再应用 `deploy/qce-patches/apply.mjs`；镜像保留上游来源、提交、许可证和修改标签。第三方及修改声明见根目录 `THIRD_PARTY_NOTICES.md`。旧的预构建镜像摘要不代表本次完整工作台镜像，UAT 必须重新构建并记录新摘要。

部署前：

1. 在仓库外生成并保存 `QQ_BRIDGE_SHARED_TOKEN` 和 32 字节以上 `QQ_DATA_MASTER_KEY`；文件权限设为 600。
2. 执行 `deploy/scripts/build-qce-image.sh` 构建固定上游镜像。
3. UAT 与正式栈分别设置唯一的 `COMPOSE_PROJECT_NAME`、`QQ_PRIVATE_NETWORK`、PostgreSQL 目录和 `QQ_RETENTION_DIR`。
4. 从仓库根目录执行：

   ```sh
   docker compose -f docker-compose.yml -f deploy/docker-compose.qq.yml config
   docker compose -f docker-compose.yml -f deploy/docker-compose.qq.yml up -d --build
   ```

后端镜像会预先创建并将 `/data/qq-imports` 设为应用用户专用的 `0700`
目录。Docker 首次挂载空的 `qq-imports` 命名卷时会保留该属主和权限；如果是在
较早版镜像下已创建的卷，发布前必须核对容器内该目录对 `app` 用户可写，
不得为规避权限问题而改成全局可写。

撤销连接会精确删除该成员的 QCE 容器和四个 QQ 实例卷；容器已不存在时可幂等重试，Docker 短暂报告“卷仍在使用”时会有限退避后继续清理。下一次连接必须重新扫码。原始聊天的 30 天加密留存位于后端独立存储，不随连接撤销提前删除。

> Docker Socket 权限很高。生产环境建议再使用只放行容器生命周期子集的 Docker Socket Proxy；QQ Bridge 已限制固定镜像、固定标签、容器命名和路由，但这不能消除 Docker Socket 本身的宿主权限风险。

## 5. 数据迁移与回滚

Flyway `V23__qq_follow_up_consultation_enrichment.sql` 建立 QQ 基础表；`V28__qq_workbench_sessions.sql` 以兼容方式增加会话类型、会话 ID、群目标成员和上下文确认字段，并更新幂等唯一约束。它们不删除业务表或重写原始聊天；旧镜像不读取新增列，因此应用镜像可回滚，数据库保留迁移结构。

发布顺序：只读预检 → PostgreSQL 逻辑备份与 SHA-256 → 隔离 UAT → 专用测试 QQ 扫码验收 → 权限回归 → 正式发布审批。任何环境均不得使用 `docker compose down -v`，也不得删除 PostgreSQL 持久化目录。

## 6. 审计与故障排查

预览、导入确认、连接撤销、招募领取、交接创建/接受/拒绝/回填、策略更新和资料补全提交均写入审计。日志不得记录 Bridge Token、QCE Token、加密密钥或原始聊天。

如预览返回 `QQ_RAW_STORE_FAILED`，先核对后端运行用户与
`/data/qq-imports` 的数字属主、模式和可写性。正常镜像中该目录归 `app`
用户所有且模式为 `0700`；修复后应同时验证密文不包含原文、应用可解密读回、其他用户无法读取。
可对发布镜像执行 `tests/uat/verify-qq-storage-image.sh <backend-image>`，它只创建并
清理自己的临时卷，不操作业务卷。

常见错误：

- `QQ_INTEGRATION_NOT_CONFIGURED`：Bridge 地址、共享令牌或主密钥缺失；
- `CUSTOMER_QQ_MISMATCH`：好友 QQ 与客户档案不一致；
- `QQ_GROUP_CONTEXT_CONFIRMATION_REQUIRED`：群聊未选择目标成员或未完成第三方内容确认；
- `QQ_MEDIA_SOURCE_FORBIDDEN`：媒体地址不是受信任 QQ 来源；
- `QCE_EXPORT_QUOTA_EXCEEDED` / `QCE_DISK_SPACE_LOW`：个人导出配额或服务器磁盘保护已触发；
- `QQ_IMPORT_DUPLICATE`：相同消息范围已经预览或导入；
- `RECRUITMENT_CLOSED`：并发领取时名额已满；
- `CONSULTATION_TIME_CONFLICT`：顾问时段重叠；
- `CONSULTATION_DAILY_CAPACITY_REACHED`：达到每日容量；
- `ENRICHMENT_PREVIEW_EXPIRED`：资料补全预览超过 24 小时。
